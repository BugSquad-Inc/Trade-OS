## 1.1 CATEGORY DEFINITION: TRADE OS IS AN EXPORT REVENUE OS

### What Trade OS is

Trade OS is an **Export Revenue Operating System**.

It combines:

1. **Vertical product ontology**  
   Leather types, HS codes, tannage, thickness, finish, certification, grade, origin, and end-use.

2. **Compliance intelligence**  
   EUDR deforestation risk, REACH chemical compliance, LWG audit status, traceability gaps, and documentation readiness.

3. **Trade lane economics**  
   Chennai/Ambur to Hamburg/Cologne/Frankfurt freight benchmarks, transit times, Incoterms, landed-cost indicators, and sample logistics.

4. **Buyer intent and account intelligence**  
   Product categories, sourcing behavior, brand positioning, procurement triggers, compliance exposure, and reachable contacts.

5. **Action layer**  
   Ranked matches, explainable scorecards, outreach drafts, follow-up sequences, meeting requests, and pilot deliverables.

### What Trade OS is not

Trade OS is not:

- A horizontal lead database like Apollo.
- A raw customs data dump like Tendata, 52wmb, Panjiva, ImportYeti, or Volza.
- A complex enterprise supply-chain graph like Altana AI.
- A trade fair exhibitor list like Lineapelle.
- A generic CRM.
- A generic SDR automation tool.
- A commodity price ticker.
- A compliance certificate repository.

### Core category statement

> **Trade OS is the operating system that helps vertical exporters find, qualify, price, compliance-check, and contact the right international buyers before competitors send another generic email.**

### Core value equation

```text
Export Revenue =
  Right Buyer
× Right Product Fit
× Right Compliance Readiness
× Right Price/Lane Economics
× Right Outreach Message
× Right Timing
```

Trade OS exists to maximize all six variables at once.

### UNFAIR ADVANTAGE 2: EUDR & REACH COMPLIANCE GAP SCORECARD

The EU Deforestation Regulation and REACH are not generic compliance checkboxes. They are revenue gates.

Trade OS converts compliance into a commercial scorecard.

### EUDR Compliance Gap Scorecard

| EUDR Dimension | What Trade OS Checks | Revenue Impact |
|---|---|---|
| Commodity scope | Is the product covered by EUDR? Cattle hides/leather, sheep, goat, etc. | Determines whether buyer can legally source |
| Geolocation | Are farm/supplier coordinates available? Polygon or point data? | Major gap for many Indian suppliers |
| Deforestation cutoff | Evidence no deforestation after Dec 30, 2020 | Required for EU market access |
| Legality | Compliance with local land/use laws | Reduces buyer risk |
| Due diligence statement | Can exporter support DDS data? | Buyer needs documentation |
| Traceability | Farm → aggregator → tannery → exporter chain | Higher traceability = higher match score |
| Country risk | India risk category, region risk, supplier risk | Affects due diligence depth |
| Tannery audit | LWG, ISO, audit reports, chemical records | Increases buyer confidence |

### REACH Compliance Gap Scorecard

| REACH Dimension | What Trade OS Checks | Revenue Impact |
|---|---|---|
| Chromium VI | Test report availability, limit compliance | Critical for leather |
| Azo dyes | Restricted arylamine compliance | Required for EU buyers |
| PCP/TeCP | Pentachlorophenol/tetrachlorophenol limits | Historical leather chemical risk |
| Formaldehyde | Limit compliance for finished leather | Important for consumer goods |
| Heavy metals | Lead, cadmium, nickel where applicable | Product safety |
| Chemical inventory | Tannery chemical list, supplier declarations | Supports buyer due diligence |
| Test lab validity | Recent third-party test reports | Increases trust |
| Product category fit | Footwear, gloves, bags, automotive, upholstery | Different buyers have different thresholds |

### Compliance score output

```text
EUDR Score: 0–100
REACH Score: 0–100
Overall Compliance Readiness: Low / Medium / High / Export-Ready
Gap Actions:
  - Obtain geolocation polygons
  - Update REACH test report
  - Obtain LWG audit evidence
  - Prepare EUDR due diligence packet
  - Create tannery traceability sheet
```

### Why this is defensible

Generic tools cannot say:

> “This German glove buyer is a strong match, but only if Butler’s Leather provides goat nappa with REACH test reports and EUDR geolocation evidence. Here is the exact gap and the outreach message to position it.”

That is a vertical revenue insight.

```text
  Hamburg / Cologne / Frankfurt / Munich / Milan / Barcelona / London
```

### Indicative lane economics

| Lane Component | Indicative Benchmark | Notes |
|---|---:|---|
| Ambur/Chennai inland transport to Chennai port | $100–$350 per shipment | Depends on distance, truck type, consolidation |
| Chennai to Hamburg FCL 20ft | $1,800–$3,500 | Volatile; must be refreshed weekly |
| Chennai to Hamburg LCL | $65–$110 per CBM | Relevant for sample/small-batch |
| Transit time | 28–35 days | Port congestion, carrier, transshipment |
| Air sample freight | $6–$12 per kg | Critical for leather swatches |
| Documentation cost | $50–$250 | COO, invoice, packing list, test reports |
| Inspection cost | $150–$500 | If buyer requires |

## 2.5 POSTGRESQL 16 MEDALLION DDL

This is the production-oriented DDL foundation.

```sql
-- =====================================================
-- TRADE OS POSTGRESQL 16 MEDALLION DDL
-- Schemas: bronze, silver, gold
-- =====================================================

BEGIN;

-- =====================================================
-- EXTENSIONS
-- =====================================================
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS vector;

-- =====================================================
-- SCHEMAS
-- =====================================================
CREATE SCHEMA IF NOT EXISTS bronze;
CREATE SCHEMA IF NOT EXISTS silver;
CREATE SCHEMA IF NOT EXISTS gold;
CREATE SCHEMA IF NOT EXISTS audit;

-- =====================================================
-- COMMON FUNCTIONS
-- =====================================================
CREATE OR REPLACE FUNCTION public.set_updated_at()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$;

CREATE OR REPLACE FUNCTION gold.notify_match_refresh()
RETURNS trigger
LANGUAGE plpgsql
AS $$
DECLARE
  payload json;
BEGIN
  IF TG_OP = 'DELETE' THEN
    payload := json_build_object(
      'table', TG_TABLE_NAME,
      'schema', TG_TABLE_SCHEMA,
      'op', TG_OP,
      'account_id', OLD.account_id
    );
  ELSE
    payload := json_build_object(
      'table', TG_TABLE_NAME,
      'schema', TG_TABLE_SCHEMA,
      'op', TG_OP,
      'account_id', NEW.account_id
    );
  END IF;

  PERFORM pg_notify('match_refresh', payload::text);
  RETURN NULL;
END;
$$;

-- =====================================================
-- BRONZE: RAW SOURCE TABLES
-- =====================================================

CREATE TABLE IF NOT EXISTS bronze.source_systems (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL UNIQUE,
  source_type text NOT NULL CHECK (source_type IN (
```

## 3.3 DAY 3: EXPLAINABLE 100-POINT SCORING SERVICE

|---|---:|

### `backend/app/services/scoring_service.py`

```python
from dataclasses import dataclass, field
from typing import Any

SCORE_VERSION = "v1.0.0"

@dataclass
class ScoreDriver:
    dimension: str
    points: float
    max: float
    evidence: str

    def to_dict(self):
        return {
            "dimension": self.dimension,
            "points": self.points,
            "max": self.max,
            "evidence": self.evidence
        }

@dataclass
class MatchScore:
    score: float
    grade: str
    drivers: list[ScoreDriver] = field(default_factory=list)

    def to_dict(self):
        return {
            "score": self.score,
            "grade": self.grade,
            "score_version": SCORE_VERSION,
            "drivers": [d.to_dict() for d in self.drivers]
        }

def grade_from_score(score: float) -> str:
    if score >= 85:
        return "A"
    if score >= 75:
        return "B"
    if score >= 65:
        return "C"
    if score >= 50:
        return "D"
    return "E"

def score_product_fit(exporter_profile: dict, buyer_products: list[dict]) -> ScoreDriver:
    max_points = 35.0
    points = 0.0
    evidence = []

    exporter_hs = set(exporter_profile.get("hs_codes", []))
    exporter_materials = set(exporter_profile.get("materials", []))
    exporter_leather_types = set(exporter_profile.get("leather_types", []))
    exporter_tannage = set(exporter_profile.get("tannage_options", []))

    for product in buyer_products:
        product_hs = product.get("hs_code")
        material = product.get("material_type")
        leather_type = product.get("leather_type")
        tannage = product.get("tannage")

        if product_hs in exporter_hs:
            points += 10
            evidence.append(f"HS {product_hs} matches exporter HS focus.")

        if material in exporter_materials:
            points += 8
            evidence.append(f"Material {material} matches exporter material capability.")

        if leather_type in exporter_leather_types:
            points += 8
            evidence.append(f"Leather type {leather_type} matches exporter capability.")

        if tannage in exporter_tannage:
            points += 5
            evidence.append(f"Tannage {tannage} matches exporter capability.")

        thickness_min = product.get("thickness_min_mm")
        thickness_max = product.get("thickness_max_mm")
        exporter_ranges = exporter_profile.get("thickness_ranges", [])

        if thickness_min is not None and thickness_max is not None:
            for r in exporter_ranges:
                # Simplified range check; production should use Postgres numrange properly
                if r.get("lower") is not None and r.get("upper") is not None:
                    if not (thickness_max < r["lower"] or thickness_min > r["upper"]):
                        points += 4
                        evidence.append(
                            f"Thickness {thickness_min}-{thickness_max}mm overlaps exporter range."
                        )
                        break

    points = min(points, max_points)

    if not evidence:
        evidence.append("No direct product overlap detected.")

    return ScoreDriver(
        dimension="product_fit",
        points=round(points, 2),
        max=max_points,
        evidence=" ".join(evidence[:3])
    )

def score_compliance(exporter_profile: dict, buyer_account: dict) -> ScoreDriver:
    max_points = 25.0
    points = 0.0
    evidence = []

    exporter_eudr = exporter_profile.get("eudr_score", 0) or 0
    exporter_reach = exporter_profile.get("reach_score", 0) or 0
    buyer_eudr = buyer_account.get("eudr_score", 0) or 0
    buyer_reach = buyer_account.get("reach_score", 0) or 0

    if exporter_eudr >= 80:
        points += 10
        evidence.append("Exporter EUDR readiness is strong.")
    elif exporter_eudr >= 65:
        points += 6
        evidence.append("Exporter EUDR readiness is moderate; documentation gaps may exist.")
    else:
        points += 2
        evidence.append("Exporter EUDR readiness is low; urgent compliance gap.")

    if exporter_reach >= 80:
        points += 10
        evidence.append("Exporter REACH readiness is strong.")
    elif exporter_reach >= 65:
        points += 6
        evidence.append("Exporter REACH readiness is moderate.")
    else:
        points += 2
        evidence.append("Exporter REACH readiness is low.")

    if buyer_eudr >= 75 and buyer_reach >= 75:
        points += 5
        evidence.append("Buyer appears compliance-aware; structured documentation will improve conversion.")

    points = min(points, max_points)

    return ScoreDriver(
        dimension="compliance_readiness",
        points=round(points, 2),
        max=max_points,
        evidence=" ".join(evidence[:3])
    )

def score_lane_economics(exporter_profile: dict, lane_benchmark: dict | None) -> ScoreDriver:
    max_points = 15.0
    points = 0.0
    evidence = []

    if lane_benchmark:
        origin = lane_benchmark.get("origin_port")
        destination = lane_benchmark.get("destination_port")
        freight_low = lane_benchmark.get("freight_low")
        freight_high = lane_benchmark.get("freight_high")

        if origin and destination:
            points += 7
            evidence.append(f"Lane {origin} to {destination} is active and benchmarked.")

        if freight_low is not None and freight_high is not None:
            if freight_high <= 3500:
                points += 5
                evidence.append("Freight benchmark is within workable range.")
            else:
                points += 2
                evidence.append("Freight benchmark is elevated; landed cost must be checked.")

        transit_min = lane_benchmark.get("transit_days_min")
        transit_max = lane_benchmark.get("transit_days_max")
        if transit_min and transit_max and transit_max <= 35:
            points += 3
            evidence.append("Transit time is acceptable for standard sea freight.")
    else:
        evidence.append("No lane benchmark available; manual freight validation required.")

    points = min(points, max_points)

    return ScoreDriver(
        dimension="lane_economics",
        points=round(points, 2),
        max=max_points,
        evidence=" ".join(evidence[:3])
    )

def score_intent_signals(signals: list[dict]) -> ScoreDriver:
    max_points = 15.0
    points = 0.0
    evidence = []

    for signal in signals:
        signal_type = signal.get("signal_type")
        severity = signal.get("severity")

        if signal_type in {"BUYER_EXPANSION", "RFQ_INTENT", "CUSTOMS_SHIPMENT"}:
            if severity == "HIGH":
                points += 6
                evidence.append(f"High-severity intent signal: {signal_type}.")
            elif severity == "MEDIUM":
                points += 4
                evidence.append(f"Medium-severity intent signal: {signal_type}.")
            else:
                points += 2
                evidence.append(f"Low-severity intent signal: {signal_type}.")

        if signal_type == "REGULATION_DEADLINE":
            points += 3
            evidence.append("Regulation deadline creates urgency.")

    points = min(points, max_points)

    if not evidence:
        evidence.append("No strong intent signals available.")

    return ScoreDriver(
        dimension="intent_signals",
        points=round(points, 2),
        max=max_points,
        evidence=" ".join(evidence[:3])
    )

def score_accessibility(contacts: list[dict]) -> ScoreDriver:
    max_points = 10.0
    points = 0.0
    evidence = []

    if not contacts:
        evidence.append("No contacts identified; outreach risk is high.")
        return ScoreDriver("accessibility", 0.0, max_points, evidence[0])

    has_email = any(c.get("email") for c in contacts)
    has_linkedin = any(c.get("linkedin_url") for c in contacts)
    high_confidence = any((c.get("confidence_score") or 0) >= 70 for c in contacts)

    if has_email:
        points += 5
        evidence.append("Email contact available.")

    if has_linkedin:
        points += 3
        evidence.append("LinkedIn contact available.")

    if high_confidence:
        points += 2
        evidence.append("At least one high-confidence contact exists.")

    points = min(points, max_points)

    return ScoreDriver(
        dimension="accessibility",
        points=round(points, 2),
        max=max_points,
        evidence=" ".join(evidence[:3])
    )

def score_match(
    exporter_profile: dict,
    buyer_account: dict,
    buyer_products: list[dict],
    buyer_signals: list[dict],
    buyer_contacts: list[dict],
    lane_benchmark: dict | None
) -> MatchScore:
    drivers = [
        score_product_fit(exporter_profile, buyer_products),
        score_compliance(exporter_profile, buyer_account),
        score_lane_economics(exporter_profile, lane_benchmark),
        score_intent_signals(buyer_signals),
        score_accessibility(buyer_contacts),
    ]

    total = sum(d.points for d in drivers)
    total = round(min(total, 100.0), 2)

    return MatchScore(
        score=total,
        grade=grade_from_score(total),
        drivers=drivers
    )
```

### Acceptance Criteria

- Each match returns score 0–100.
- Each match returns five driver objects.
- Drivers include evidence strings.
- Score is deterministic for same inputs.
- Score history can be written to `gold.match_score_history`.

## 4.4 WRITTEN 14-DAY 5-MATCH REFUND CRITERIA

### Qualified Match Definition

   - Buyer needs leather or materials within HS 4101–4107, or a directly related leather product category.

2. **Material overlap**
   - Buyer requirement overlaps with exporter capability in at least one of:
     - Animal source
     - Leather type
     - Tannage
     - Thickness range
     - End use

3. **Verifiable buyer profile**
   - Buyer has:
     - Company name
     - Country
     - Website or public profile
     - Product category
     - Plausible procurement relevance

4. **Actionable compliance position**
   - Match includes either:
     - Exporter compliance readiness sufficient for outreach, or
     - A clearly defined compliance gap with a practical remediation action.

5. **Reachable contact or outreach path**
   - At least one of:

## 5.2.3 PGVECTOR HYBRID SEARCH

### Search objective

Allow users to ask natural commercial questions:

```text
Find German buyers of bovine full-grain leather for automotive use.
Find buyers likely to need EUDR documentation support.
Find glove manufacturers needing goat nappa.
Find companies similar to Bader.
Find buyers affected by REACH chemical documentation gaps.
```

### Hybrid search architecture

```text
User Query
  │
  ├── Semantic embedding search using pgvector
  │
  ├── Keyword/full-text search using tsvector/ts_rank_cd
  │
  ├── Structured filters:
  │     country, HS code, material, thickness, compliance score
  │
  └── Reciprocal Rank Fusion
        │
        ▼
     Ranked Accounts / Products / Signals
```

### Example SQL pattern

```sql
WITH vector_results AS (
  SELECT
    entity_id,
    1 - (embedding <=> :query_embedding) AS vector_score
  FROM gold.document_embeddings
  WHERE entity_type = 'ACCOUNT'
  ORDER BY embedding <=> :query_embedding
  LIMIT 50
),
fts_results AS (
  SELECT
    id AS entity_id,
    ts_rank_cd(search_vector, plainto_tsquery('simple', :query_text)) AS fts_score
  FROM silver.accounts
  WHERE search_vector @@ plainto_tsquery('simple', :query_text)
  ORDER BY fts_score DESC
  LIMIT 50
),
fused AS (
  SELECT
    COALESCE(v.entity_id, f.entity_id) AS entity_id,
    COALESCE(1.0 / (60 + ROW_NUMBER() OVER (ORDER BY v.vector_score DESC)), 0) AS vector_rrf,
    COALESCE(1.0 / (60 + ROW_NUMBER() OVER (ORDER BY f.fts_score DESC)), 0) AS fts_rrf
  FROM vector_results v
  FULL OUTER JOIN fts_results f ON v.entity_id = f.entity_id
)
SELECT
  entity_id,
  SUM(vector_rrf + fts_rrf) AS hybrid_score
FROM fused
GROUP BY entity_id
ORDER BY hybrid_score DESC
LIMIT 20;
```

> Production implementation should tune RRF constant, weights, filters, and pagination.
